# Plan: Pixel Stair Game Redesign

## Goal
회사 건물 내부와 창밖 네온 야경을 배경으로, 젊은 회사원과 조금 나이 든 회사원이 같은 계단을 오르는 코믹한 픽셀 게임을 만든다. 한 방향 구간은 실제 계단 기준 4~6칸이며 연속한 두 구간의 길이는 다르다. 입력 판정·미리보기·지나온 경로·추격자 위치가 하나의 경로를 공유한다. 중앙 플레이어, 뒤 4칸과 앞 6칸, 몸 아래쪽이 계단에 가려지는 추격자를 표시한다.

## Task Roadmap
1. T01: 결정적인 랜덤 경로와 직전 길이를 반복하지 않는 4~6칸 구간을 엔진에 연결한다. 기존 화면과 조작은 실행 가능한 상태를 유지한다.
2. T02: 같은 경로로 앞뒤 계단과 두 인물을 배치하고 이동·가림·잡힘을 연결한다. 이 작업에서는 기존 캐릭터 그림을 임시로 재사용한다.
3. T03: 장면을 젊은/조금 나이 든 회사원, 실내 계단실과 네온 야경의 픽셀아트로 교체한다.
4. T04: HUD·버튼·설정·오디오 설정·결과·랭킹을 픽셀 디자인으로 통일하고 반응형 흐름을 확인한다.

## Architecture and Boundaries
- 경로는 런타임 `GameState.route`에 둔다. 최소 뒤 4칸과 앞 18칸을 보관하고, 화면에는 앞 6칸만 표시한다. 앞 18칸은 최대 6칸 구간 뒤의 모퉁이 판정과 미리보기를 모두 보장하는 고정 버퍼다.
- 생성기 메타데이터에 마지막 생성 구간의 전체 길이 `tailRunLength`를 보관한다. 다음 길이는 4·5·6에서 그 값을 제외한 두 후보 중 하나를 고른다. 재추첨 반복문은 사용하지 않는다.
- 랜덤 값은 게임 생성 때 한 번 받아 내부 난수 상태를 만든다. 이후 경로 보충은 상태에 든 난수 값으로 결정적으로 계산하여 React updater 재실행에도 같은 입력이 같은 결과를 낸다.
- `straightStepsRemaining`은 경로에서 계산하는 호환 필드다. 방향 전환 J가 새 방향 구간의 첫 계단을 소비하므로, 이후 남은 D 횟수는 해당 구간 길이보다 1 작다.
- 아트는 현재 SVG 렌더러를 확장하여 정수 좌표의 픽셀 도형으로 작성한다. 새로운 이미지 생성 서비스, 폰트 CDN, 렌더링 패키지 없이 저장소 안에서 편집 가능한 자산을 만든다.
- 잡힘·점수 팝업·발소리·넘어짐 소리·30계단 이벤트·Entra 로그인·로컬 데모·기록/오디오 저장 형식은 기존 동작을 연결한다. 런타임 경로는 localStorage에 저장하지 않는다.

## Regression Traps
- 독립적으로 미래 계단을 다시 랜덤 생성하면 보이는 방향과 D/J 판정이 달라진다. 렌더링은 난수를 소비하지 않는다.
- J를 구간 길이에 추가로 더하면 4~6칸이 5~7칸이 된다. 실제 경로 노드의 연속 방향 길이를 검증한다. 직전 길이 비교에도 남은 D 횟수가 아니라 J를 포함한 구간 전체 길이를 사용한다.
- 과거 경로를 모두 누적하면 무한 게임에서 메모리가 증가한다. 완료한 구간도 뒤 4칸 밖은 정리한다.
- 추격자의 방향은 플레이어의 현재 방향이 아니라 추격자가 밟은 경로 노드에서 가져온다.
- 500ms 경계에서 연속 실수를 받으면 `lastMistake`가 true→true일 수 있다. `recoveryEndsAt`의 변화로 새 실수를 구별한다.
- 전체 계단 앞면을 마지막에 덮어 그리면 접힌 경로에서 얼굴까지 가려진다. 자기 발판 가림과 이동 중 발 부분 마스크만 사용한다.
- 기존 모바일 게임 오버 축소 규칙, 데스크톱 조작 버튼 숨김, 오디오 CSS와 reduced-motion 선택자 우선순위를 확인한다.

## Adjacent Findings — Outside This Plan
- 설정 도움말의 "세 번 실수하면 게임이 끝납니다"는 실제로 세 번 잡혀야 종료되는 규칙과 다르다. 문구 정정은 별도 사용자 선택 항목이다.
- `src/App.test.tsx`는 설정창을 열지 않고 계정·오디오 컨트롤이 보인다고 기대한다. 현재 `GameScreen`은 이 내용을 설정창 안에 둔다. 테스트를 실행해 실패를 확인한 것은 아니며, 이번 계획에서는 이 기존 통합 테스트 기대값을 임의로 변경하지 않는다.
- 위 두 항목의 처리 여부는 사용자에게 보고한다. 이것을 이유로 T01~T04에 별도 작업을 추가하지 않는다.
