# Decisions: Time Ranking and Office Ending

- Date: 2026-10-28
- Status: Confirmed
- Scope: 메인 내려오기 게임의 시간 랭킹·퇴근 엔딩과 공용 픽셀 계단 디자인.

## D01. Ranking order

- **Chosen (사용자 요청)**: 도전 단계 내림차순 → 해당 단계 점수 내림차순 → 해당 단계에서 남은 시간 내림차순. 같은 단계·같은 점수일 때 남은 시간이 많은 사람이 더 높은 순위다. 중도 잡힘과 클리어 기록 모두 이 기준을 사용한다.
- **Chosen (사용자 선택 1)**: 남은 시간을 0.01초 단위로 비교하고 `남은 시간 12.34초`처럼 표시한다.
- **Rationale**: 같은 점수에서도 더 빠르게 진행한 기록을 구별한다. 순위 비교 단위와 표시 단위를 일치시켜 보이는 시간이 같은데 숨은 정밀도 때문에 순서가 달라지는 일을 방지한다.
- **Code-derived**: 세 항목까지 같으면 기존처럼 먼저 달성한 기록을 우선한다. 계정별 최고 기록은 단계·점수·남은 시간을 같은 도전의 묶음으로 비교하고 저장한다. 각각 다른 도전의 최댓값을 합치지 않는다.
- **Engineering**: 순위 시간은 음수가 아닌 정수 centiseconds(1단위=0.01초)로 정규화한다. `floor(max(0, remainingMs) / 10)`를 비교와 표시에 공통으로 사용한다. 실제 필드명/검증 스키마는 계획에서 확정한다.

## D02. Capture remaining time at the real result boundary

- **Chosen**: 단계 클리어 또는 잡힘 순간의 해당 단계 남은 시간을 기록한다. 시간 초과는 0.00초다. 체크포인트에서 그만두는 경우 클리어 순간에 고정한 시간을 사용한다.
- **Rationale**: 체크포인트 선택 대기, 잡힘 연출, 랭킹 저장 처리, 퇴근 엔딩 소요 시간이 성적을 바꾸지 않아야 한다.
- **Code-derived**: `gameEngine.ts`는 종료/체크포인트에서 `stageEndsAt`을 null로 만들고 `getStageSecondsLeft`는 종료 후 0을 반환한다. 따라서 종료 후 HUD의 값을 읽어 저장하면 모든 기록이 0이 된다. 엔진의 전환 직전에 별도 성적 스냅샷을 만들어 보존해야 한다.
- **Engineering**: 늦은 tick의 잡힘은 callback 도착 시간이 아니라 실제 NPC 접촉 deadline에서 계산한다. 클리어는 성공 입력의 처리 시각을 사용한다. 설정 pause로 이동한 stage deadline을 반영한다. Continue는 새 단계 점수0과 새 제한시간으로 시작하며 이전 단계 스냅샷과 혼합하지 않는다.

## D03. Save at every clear and at failure

- **Chosen (사용자 선택 1)**: 각 단계 클리어 즉시 랭킹 후보를 저장한다. 이후 다음 단계에서 실패하거나 클리어하면 같은 비교 기준으로 더 높은 기록을 반영한다.
- **Rationale**: 체크포인트 이후 계속하기/그만두기 선택과 관계없이 클리어 성적을 보존한다.
- **Code-derived**: 현재 `GameScreen.tsx`의 랭킹 effect는 `status === game-over`에서만 실행한다. 이를 체크포인트 클리어까지 확장해야 한다. 현재 해금 진행도는 클리어 즉시 별도로 저장되므로 랭킹과 진행도 저장은 각자의 오류 상태를 처리한다.
- **Engineering**: StrictMode effect 재실행, 체크포인트에서 그만두기, 엔딩 완료/결과 표시로 같은 성적이 중복 저장되지 않도록 한다. 개인 최고 기록 갱신에도 시간 비교를 적용한다. 기존 브라우저 로컬 계정별 TOP10 구조를 사용한다.

## D04. Reset rankings and preserve stage unlocks

- **Chosen (사용자 선택 2)**: 기존 랭킹만 초기화하고 단계 해금 이력은 유지한다.
- **Rationale**: 기존 랭킹에는 시간 성적이 없으므로 새 기준으로 다시 기록한다.
- **Code-derived**: 메인 기록은 `stair-descent:leaderboard:v1`, 해금은 `stair-descent:stage-progress:v1`에 분리되어 있다. 신규 시간 랭킹에 별도 버전 키를 사용하고 구 랭킹만 정리한다. 이미 생성된 새 시간 랭킹을 재방문/재시도마다 초기화하지 않는다.
- **Engineering**: 기존 ascent→descent 전환의 reset marker를 재실행해 해금을 삭제하지 않는다. 인증·오디오·새 진행도는 보존한다. 저장소 차단/정리 실패에도 플레이가 가능하고 새 유효 성적을 보호한다.

## D05. Automatic office-exit ending

- **Chosen (사용자 선택 1)**: 5단계 클리어 시 약4초의 자동 픽셀 연출을 보여준다. 순서: 1층 도착 → 출입문 열림 → 젊은 회사원이 문 밖으로 걸어나감 → `퇴근 완료!` → 결과 및 랭킹 표시.
- **Rationale**: 회사 안 계단을 내려온 도전이 실제 퇴근으로 이어지는 마무리를 제공한다.
- **Code-derived**: 기존 젊은 회사원 PixelOfficer와 회사/네온 야경의 픽셀 분위기를 연결한다. 메인 5단계 클리어에서 발동하며 중도 잡힘/시간 초과/체크포인트 그만두기는 기존 결과 흐름을 사용한다. 단독 로컬 실험은1단계만 제공한다.
- **Engineering**: 성적 저장/해금은 5단계 클리어 즉시 처리하며 엔딩 완료를 기다리지 않는다. 엔딩 동안 게임 진행 입력과 추격을 종료하고 늦은 콜백으로 결과를 덮어쓰지 않는다. motion-reduce 사용자는 정적인 퇴근 완료 장면과 결과로 접근 가능하게 한다. 엔딩 타이머는 재시작/unmount에서 정리하고 결과 표시 후 키보드 초점을 적절하게 이동한다.

## D06. Office emergency staircase design

- **Chosen (사용자 선택 1)**: 회사 비상계단형 픽셀 디자인. 밝은 회색 콘크리트 윗면, 진한 옆면, 발판 끝 노란 미끄럼 방지선을 사용한다.
- **Rationale**: 어두운 회사 배경에서 계단·캐릭터·장애물이 읽히고 퇴근 설정과 어울린다.
- **Code-derived**: 현재 `PixelStair.tsx`는 청회색 윗면/남색 앞면/청록색 모서리를 SVG의 top/front로 분리해 렌더링한다. 공용 컴포넌트에 새 재질·팔레트를 적용하므로 메인과 단독 테스트 화면에 함께 반영한다.
- **Engineering**: 실제 계단 위치/방향과 발 착지점, top→캐릭터→front의 가림 순서를 기준으로 디자인한다. 기존 경로 긴5~9/짧은1~3, 장애물 판정, 점프, 코너 입력과 일치하는 발판을 그린다. 콘크리트 무늬는 렌더마다 바뀌는 난수 없이 결정적으로 표현한다.

## D07. Existing gameplay baseline

- **Code-derived**: 목표150/200/250/300/350점, 시간90/75/65/60/50초, 단계별 장애물10/20/30/40/50%, 기본 추격600/500/400/300/250ms, 거리30칸부터50ms·7칸에서해제, 넘어짐 회복500ms/가속외추격250ms가 현재 기준이다.
- **Scope interpretation**: 이번 사용자 요청은 시간 순위·단계 클리어 즉시 랭킹·기존 랭킹 초기화·퇴근 엔딩·계단 외형이다. 별도 새로운 단계/엔진/배포/서버 랭킹은 결정에 포함하지 않는다.

## Findings to report

- 현재 종료 시각을 버리는 구조와 terminal-only 저장은 D02/D03 구현에 필요한 수정 사항이다. 단순히 랭킹 sort만 추가해서는 요청을 충족할 수 없다.
- `PixelStair`가 공용이어서 두 화면 디자인에 영향이 있으며 단독 실험의 무저장/1단계 조건을 계획의 회귀 경계로 명시한다.
- 추가 범위 밖 결함: 특이사항 없음.
