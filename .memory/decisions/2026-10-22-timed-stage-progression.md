# Decisions: Timed Stage Progression

- Date: 2026-10-22
- Status: Confirmed
- Workflow: grill-me interview. This document records decisions only; implementation and planning have not started.

## D01. 단계 범위와 임시 2단계
- **Chosen (user)**: 현재는 최대 2단계까지만 만든다. 1단계의 진입 목표를 달성하면 2단계로 넘어간다.
- **Chosen (user, revised)**: 2단계는 우선 시간제한 없이 계속 플레이한다. 2단계의 별도 클리어 목표/제한시간은 나중에 추가한다. 제안되었던 '추가 90초/누적 600점 최종 클리어'는 채택하지 않았다.
- **Existing rules retained (code-derived)**: 2단계에서도 기존 실수·추격·잡힘 규칙을 사용하고, 기회를 모두 소진하면 게임이 종료된다. 3단계나 무한 반복 승급은 만들지 않는다.
- **Rationale**: 먼저 1단계의 시간/점수 조건과 단계 랭킹을 확인하고 2단계 세부 설계는 이후 변경할 수 있게 한다.

## D02. 1단계 목표와 제한시간
- **Chosen (user)**: 1단계는 1분 30초(90초) 안에 300점을 채우면 2단계로 진입한다.
- **Derived timing contract**: 시작하기/다시 시작을 눌러 실제 게임을 시작할 때 1단계의 90초가 시작된다. 대기 화면에서는 시간이 줄지 않는다.
- **Derived score contract**: 기준은 실제 누적 점수이며 계단 개수가 아니다. 기존 30계단 보너스의 한 칸당 2점도 포함한다. 299점에서 보너스 입력으로 301점이 되어도 300점 이상이므로 승급한다.
- **Derived boundary contract**: 유효한 정답 입력으로 300점 이상이 되면 그 입력에서 즉시 한 번만 승급한다. 기존 엔진의 '먼저 만료 처리, 그 뒤 입력 판정' 순서를 유지한다. 마감 시각 이상인 입력은 시간 초과로 처리하고, 표시상 마지막 1초의 남은 밀리초 안에서 도착한 입력은 유효하다.
- **Rationale**: '90초 안에 300점'이라는 조건과 기존 보너스 점수 계산을 일치시키며 경계 시각이나 2점 입력에서 판정이 뒤집히지 않게 한다.

## D03. 시간 초과와 기존 잡힘 종료
- **Chosen (user)**: 90초 안에 300점에 도달하지 못하면 게임을 종료하고 결과와 도달 단계 기록을 표시한다. 시간 초과 후 1단계에서 계속 플레이하는 안은 채택하지 않았다.
- **Existing rules retained (code-derived)**: 시간 만료 전에 기존 잡힘으로 모든 기회를 소진해도 게임은 종료된다. 실수 후 500ms 회복 동안에도 1단계 시간은 흐른다.
- **Derived result contract**: 실패 사유가 제한시간 초과인지 잡힘인지 구분하여 결과에 전달한다. 시간 초과 자체를 추격자의 잡힘/접촉 애니메이션으로 취급하지 않는다.
- **Derived lifecycle contract**: 입력하지 않아도 마감 시각이 되면 종료되어야 한다. 시간 초과는 점수를 깎거나 잡힘 횟수를 추가하지 않는다. 종료 후 점수/단계가 바뀌거나 승급하지 않아야 한다.
- **Rationale**: 사용자가 선택한 시간 초과 종료를 기존 추격 게임과 함께 동작시키고 종료 원인을 이해할 수 있게 한다.

## D04. 2단계 진입 시 회복과 유지 항목
- **Chosen (user)**: 2단계 진입 시 누적 점수와 올라온 계단은 유지하며, 기회는 3회·추격자 거리는 4칸으로 회복한다.
- **Existing behavior retained (code-derived)**: 같은 경로와 현재 위치에서 계속 플레이한다. 기존 4~6칸 랜덤 구간, 직전 구간 길이 반복 금지, D/J/터치 조작, 픽셀 장면과 추격 규칙은 유지한다.
- **Scope-preserving interpretation**: 별도 변경을 요청하지 않은 보너스 게이지/진행 중 보너스/음악 상태도 이어간다. 2단계에서 보너스가 발동하거나 점수가 더 높아졌다는 이유로 기회를 다시 회복하지 않는다.
- **Rationale**: 단계 진입 보상을 제공하면서도 진행한 경로와 누적 기록이 끊기지 않게 한다. 2단계의 난이도·배경 변경은 이번 요구에 추가하지 않는다.

## D05. HUD의 단계와 남은 시간
- **Chosen (user)**: 점수판 옆에 남은 시간을 보여 주는 초시계를 배치한다.
- **Derived presentation**: 1단계에서는 `01:30`처럼 분:초 형식으로 남은 시간을 표시하고 0 아래로 내려가지 않게 한다. 소수 초는 표시하지 않으며 남은 밀리초를 올림하여 보여 준다.
- **Derived presentation**: 현재 `1단계`/`2단계`를 게임 안에서 확인할 수 있게 한다. 2단계에 진입하면 제한시간은 더 이상 줄지 않고 `제한 없음`으로 표시한다.
- **Layout constraint**: 기존 점수·기회·보너스 게이지·우측 상단 설정과 함께 게임 내부 HUD에 배치한다. 좁은 화면에서도 숫자와 설정 버튼, 실제 경로가 겹치지 않게 한다.
- **Rationale**: 남은 시간과 승급 여부를 플레이 도중 즉시 알 수 있고, 2단계에 남은 1단계 시간이 계속 흐르는 것으로 오해하지 않게 한다.

## D06. 설정창에서 일시정지
- **Chosen (user)**: 설정창을 열면 1단계 제한시간과 기존 보너스 타이머를 함께 일시정지하고, 닫으면 남은 시간부터 재개한다.
- **Existing behavior retained (code-derived)**: 설정창 안에서는 D/J/터치 플레이 입력을 차단한다. 설정 닫기·Escape·포커스 순환·닫은 뒤 포커스 복귀·오디오 설정은 유지한다.
- **Derived timer contract**: 아직 유효한 제한시간의 마감 시각과 보너스 종료 시각에 실제로 설정창이 열려 있던 시간을 동일하게 반영한다. 이미 마감된 1단계를 설정 진입으로 되살리지 않는다.
- **Existing clock convention retained (code-derived)**: 별도 설정 일시정지가 아닌 일반 탭 숨김/전환에서는 기존 절대 시각 기반 타이머처럼 시간이 흐른다. 화면 복귀와 입력 처리 때 만료를 다시 확인한다.
- **Rationale**: 현재 설정창의 보너스 일시정지 방식과 일관되게 제한시간도 멈추게 한다.

## D07. 단계 우선 랭킹
- **Chosen (user)**: 도달 단계가 높은 사람을 먼저 표시하고, 같은 단계에서는 점수가 높은 순으로 정렬한다. 표시 예시는 `2단계 · 850점`, `1단계 · 275점`이다.
- **Existing tie convention retained (code-derived)**: 단계와 점수가 모두 같으면 기존처럼 먼저 달성해 저장된 기록을 우선한다. 개인의 동일한 최고 기록을 다시 저장하여 달성 시각을 바꾸지 않는다.
- **Derived record contract**: '도달 단계'를 저장한다. 1단계 시간 초과/기회 소진 기록은 1단계이고 2단계 진입 후 종료된 기록은 2단계다. 아직 2단계 최종 클리어 개념은 없다.
- **Derived best-record contract**: 개인 최고 기록 갱신에도 같은 단계→점수 비교를 사용한다. 기록의 단계와 점수는 같은 한 판에서 얻은 쌍으로 저장하며, 서로 다른 판의 단계와 최고 점수를 합치지 않는다.
- **Existing persistence retained (code-derived)**: 게임 종료 시 한 번 저장하고 현재 브라우저의 TOP10과 현재 사용자 강조를 유지한다. 이번 요청으로 사내 공유 서버 랭킹이나 중간 자동 저장을 추가하지 않는다.
- **Rationale**: 사용자가 선택한 단계 중심 비교와 같은 단계 내 성과 차이를 함께 표현한다.

## D08. 기존 점수 랭킹 초기화
- **Chosen (user)**: 지금까지 기록된 기존 점수 랭킹은 지워도 된다. 보관/1단계 기록으로 가져오기 대신 새 단계 랭킹을 시작한다.
- **Implementation boundary**: 새 규칙 적용 시 기존 `stair-climb:leaderboard:v1` 점수 기록을 정리하고, 단계 필드가 있는 새 버전의 랭킹 저장 형식을 사용한다. 현재 인터뷰에서는 실제 브라우저 기록을 삭제하지 않는다.
- **Deletion scope**: 초기화 대상은 기존 랭킹 키뿐이다. 오디오 설정 `stair-climb:audio:v1`, 인증 관련 데이터와 다른 localStorage 키는 건드리지 않는다. `localStorage.clear()`를 사용하지 않는다.
- **Failure behavior retained (code-derived)**: 저장소 접근/삭제/저장이 불가능해도 게임 플레이와 결과 화면을 유지하고 관련 실패를 알린다. 새 형식에 구형 점수를 섞거나 구형 기록의 달성 단계를 임의로 추정하지 않는다.
- **Rationale**: 기존 기록에는 단계와 90초 내 달성 여부가 없어 새 조건과 공정하게 비교할 수 없고, 사용자가 기존 기록 초기화를 허용했다.

## D09. 구현 시 지켜야 할 기존 구조
- **Code-derived**: `GameState`에는 아직 단계/제한시간 필드가 없고, `tickGame`은 보너스와 회복 종료만 처리한다. 현재 단계, 1단계 마감 시각, 종료 사유를 명시적으로 표현해야 한다.
- **Code-derived**: `GameScreen`의 interval은 지금은 보너스나 회복 타이머가 있을 때만 실행된다. 아무 입력 없이 대기하는 1단계에서도 남은 시간 표시와 만료 처리가 진행되도록 조건을 확장해야 한다.
- **Code-derived**: 설정 닫기는 현재 보너스 시각만 연장한다. 같은 일시정지 구간을 새 단계 제한시간에도 한 번만 적용해야 한다.
- **Code-derived**: `LeaderboardEntry`, 검증, 읽기/쓰기, 개인 최고 비교와 TOP10 정렬, 결과/랭킹 UI가 함께 단계 정보를 다뤄야 한다. 시각 표시만 단계로 바꾸고 저장/정렬을 점수 기준으로 남기지 않는다.
- **Scope**: 기존 React/픽셀 UI/Entra 로그인/로컬 데모/오디오/경로 모델을 사용한다. 새 외부 서비스나 패키지, 2단계 최종 목표를 추가하지 않는다.
- **Rationale**: 표시·엔진 판정·타이머·저장·랭킹 사이에 서로 다른 규칙이 생기는 것을 막는다. 구체적인 타입/심볼/검증 명령은 `/memory-plan`에서 Task 청사진으로 작성한다.

- 기존 도움말의 '세 번 실수' 문구와 실제 세 번 잡힘 종료 규칙의 불일치, `src/App.test.tsx`의 오래된 설정창 기대값은 이전 계획에서 보고된 별도 검토 항목이다. 이번 인터뷰로 해당 수정 범위를 추가하지 않는다.
- 기존 bundle 크기 경고와 사용하지 않는 옛 SVG CSS 정리도 별도 검토 대상으로 남긴다.
