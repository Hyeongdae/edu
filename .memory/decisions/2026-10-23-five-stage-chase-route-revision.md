## D01. 단계별 장애물 확률과 추격 속도
- **Chosen (user)**: 장애물 확률은10/20/30/40/50%로 변경한다. 추격자는 아래 간격마다 같은 경로에서 한 계단씩 올라온다. 우선 이 속도로 테스트하고 이후 조정한다.

| 단계 | 제한시간 (유지) | 누적 목표 (유지) | 긴 구간당 장애물 확률 | 추격자 한 칸 이동 간격 |
| :--- | :--- | :--- | :--- | :--- |
| 1 | 90초 | 300점 | 10% | 1초 |
| 2 | 75초 | 600점 | 20% | 0.8초 |
| 3 | 65초 | 900점 | 30% | 0.6초 |
| 4 | 60초 | 1200점 | 40% | 0.5초 |
| 5 | 50초 | 1500점 | 50% | 0.4초 |

- **Rationale**: 단계가 올라갈수록 장애물 빈도와 추격 속도를 높인다. 추후 수치 조정이 쉽도록 단계별 규칙표로 관리한다.

## D02. 긴 구간과 짧은 구간의 랜덤 조합
- **Chosen (user)**: 긴 구간5~9칸, 짧은 구간1~3칸으로 한다. 기존의 모든 직선4~8칸 규칙을 대체한다.
- **Chosen (user)**: `긴→짧→긴`과 `긴→짧→짧→긴`을 랜덤으로 섞는다.
- **Derived sequence interpretation**: 긴 구간 뒤에 짧은 구간1개 또는2개를 선택하고 다음 긴 구간으로 이어진다. 패턴의 끝과 다음 패턴의 시작 긴 구간은 공유하며 긴 구간2개를 별도로 연속 추가하지 않는다.
- **Examples**: `오른쪽7 → 왼쪽2 → 오른쪽8`, `오른쪽7 → 왼쪽1 → 오른쪽2 → 왼쪽8`. 숫자는 해당 방향의 실제 계단 수다. J는 방향을 바꾸면서 첫 한 칸을 올라간다.
- **Existing convention retained**: 구간마다 방향을 반전하고 최초 방향은 오른쪽이다. 인접 구간 길이 비반복은 유지한다. 두 짧은 구간이 연속되면 길이를 다르게 뽑는다. 사이에 짧은 구간이 있는 두 긴 구간까지 같은 길이를 금지하는 새 규칙은 추가하지 않는다.
- **Implementation default**: 짧은 구간 개수1/2와 각 허용 길이는 가능한 후보에서 균등 선택한다. 이 비율을 사용자가 별도 지정한 것은 아니다. 기존처럼 명시적인 난수 상태를 보관하고 생성한 경로를 다시 뽑지 않는다.
- **Rationale**: 긴 직진과 짧은 방향 전환을 섞어 계단 모양과 조작 리듬을 바꾼다.

## D03. 긴 구간에만 장애물 배치
- **Chosen (user)**: 장애물은5~9칸의 긴 구간에만 놓는다. 짧은 구간에는3칸 가운데라도 놓지 않는다.
- **Existing contract retained**: 표의 확률은 긴 구간당 등장 확률이며 계단 한 칸당 확률이 아니다. 구간당 최대1개, 첫 칸/마지막 칸 제외, 같은 방향의 안전한 출발·장애물·착지를 보장한다.
- **Existing stability retained**: '장애물 없음'도 결정으로 보관한다. 이미 보인 구간은 승급/렌더/resize로 바꾸지 않고 새로 확정할 미래 긴 구간에 새 단계 확률을 적용한다.
- **Rationale**: 짧은 구간은 방향 전환, 긴 구간은 장애물을 읽고 점프하는 조작에 집중한다.

## D04. 시간에 따른 독립 추격
- **Chosen (user)**: 플레이어가 멈춰 있어도 추격자는 시간마다 한 계단씩 이동한다. 플레이어 성공 이동 때 추격자도 같은 칸 수만큼 전진하던 규칙은 제거한다.
- **Derived distance contract**: 플레이어의 오르기는 거리를1칸, 성공 점프는2칸 벌리고 추격자의 한 칸 전진은 거리를1칸 줄인다. 거리를4칸으로 제한하지 않는다. 추격자가 플레이어 위치에 도달하면 잡힘이다.
- **Existing start/catch contract retained**: 시작은 기회3회/거리4칸이다. 잡힘 때만 기회1회 차감, 남은 기회가 있으면 현재 플레이어 뒤4칸으로 추격자를 되돌린다. 기회0이면 종료한다. 기존500ms 잡힘/회복 연출과 플레이어 위치·점수 유지를 따른다.
- **Existing promotion contract retained**: 승급은 기회3회/거리4칸 회복, 점수·경로·보너스 유지다. 시작/잡힘 후 재배치/승급 시 해당 시점부터 온전한 새 추격 간격을 센다. 이전 단계의 남은 이동 시간을 이월하지 않는다.
- **Existing obstacle scope retained**: 장애물은 플레이어의 조작 과제다. 추격자는 장애물로 멈추거나 별도 점프 입력/기회 차감을 요구하지 않는다.
- **Lifecycle derived from existing clocks**: 설정창에서는 단계·보너스와 함께 추격 시계를 멈추고 닫을 때 한 번만 보정한다. 대기/종료 중에는 추격하지 않는다. 일반 숨김 탭의 시간은 흐르며 복귀 시 실제 경과한 추격을 반영한다. 화면 갱신이 늦었다고 여러 이동을 한 번으로 축소하지 않는다.
- **Boundary contract**: 유효 입력 전에 시간에 의한 이동/잡힘을 반영한다. 이미 잡힐 시각에 도달했다면 같은 시각의 입력으로 잡힘을 취소하지 않는다. 만료한 게임은 입력으로 승급/클리어시키지 않는다. 세부 시간 처리 순서와 상태 필드는 후속 계획에서 명시한다.
- **Rationale**: 각 인물의 실제 경로 위치와 이동 시계가 있어야 속도 차이와 멈춘 시간이 거리로 드러난다.

## D05. 넘어짐은 정지 시간만 벌점
- **Chosen (user)**: 오입력은 제자리에서0.5초 동안 넘어진다. 그동안 추격자는 정상 속도로 계속 올라온다. 기존의 오입력 즉시 추격자 한 칸 전진 벌점은 제거한다.
- **Existing contract retained**: 잘못된 D/J, 장애물로 걸어가기, 장애물이 없는 곳에서 Space는 같은 실패다. 실패에는 이동·점수·이벤트 충전이 없다. 회복 중 입력은 무시하고 실제 잡힘 때만 기회를 차감한다.
- **Derived presentation contract**: 오입력 없이 시간 경과만으로 잡혀도 잡힘/기회 차감/종료가 표시되어야 한다. 시간에 의한 잡힘을 자동으로 오입력 소리 이벤트로 간주하지 않는다. 새 음원은 요청하지 않았다.
- **Rationale**: 움직이지 못한 시간 자체가 벌점이므로 추가 한 칸 벌점을 중복 적용하지 않는다.

## D06. 유지할 기존 확정 요구
- **Retained**: 누적300/600/900/1200/1500점,5단계 최종 클리어,승급 시 새 제한시간,누적 점수·보너스 유지,마감 우선/시간 초과 종료는 원 결정문을 따른다.
- **Retained**: D 한 칸/J 방향 바꾸며 한 칸/Space 장애물 다음 계단까지2칸,일반 점프2점·보너스4점,30계단마다30초 보너스와 한 입력의 원자적 이벤트 경계도 유지한다.
- **Retained**: 모바일 앞으로 / 가깝게 붙인 방향 바꾸기·점프,중복 입력 방지,성공 모션 완료를 기다리는 추가 입력 잠금 없음,큰 글자와 reduced-motion 대응을 유지한다.
- **Retained**: 랭킹은 단계→점수→먼저 달성한 시각 순이고 종료 때만 저장한다. 승인된 구형v1/v2 정리와v3/audio/auth/다른 키 보존은 유지한다. 인터뷰에서 실제 기록을 삭제하지 않는다.
- **Retained**: 회사 내부/창문 네온 야경/젊은 회사원 플레이어/나이 든 회사원 추격자의 픽셀 스타일,인증과 로컬 데모 경계는 변경하지 않는다.
- **Rationale**: 이번 요청은 계단·장애물 빈도·추격 규칙 변경이다. 다른 확정 기능은 재설계하지 않는다.

## D07. 확인한 코드 제약과 재계획
- **Code-derived**: 현재 `stairSceneModel.ts`는 추격 거리1~4칸만 허용하고 `stairRoute.ts`는 플레이어 뒤4칸만 보관한다. 새 독립 추격에는 실제 추격자 위치·시계와 두 인물에게 필요한 과거 경로 보존이 필요하다. 거리를4로 자르거나 가짜 위치로 표시하지 않는다.
- **Derived presentation default**: 기존 플레이어 중심 카메라를 유지한다. 멀어진 추격자는 화면 밖에 있을 수 있지만 실제 위치와 거리 표시는 유지한다. 화면 안에 가짜 추격자를 추가하지 않는다.
- **Code-derived**: 현재 `GameScreen.tsx`의 추격 애니메이션은 플레이어 성공 이동/실수에 연결되어 있다. 추격자의 자체 전진/잡힘을 기준으로 갱신하도록 분리한다. 무입력 상태에서도 추격과 종료가 발생해야 한다.
- **Code-derived**: 기존 계획은4~8칸/20~80%/고정 거리·과거4칸 보관을 전제로 한다. 첫 Task의 공통 규칙표부터 달라지므로 기존 청사진을 그대로 실행하지 않고 `five-stage-obstacle-jump`를 재계획한다.
- **Future validation**: 긴5~9/짧은1~3/두 패턴 혼합,짧은 구간 무장애물/긴 구간 확률·안전 착지,독립 추격 간격/무입력 잡힘/성공 이동과 점프의 거리 증가/실수 즉시 전진 없음,승급·잡힘·설정 pause·숨김 복귀,4칸 초과 거리/경로 보존/화면 밖 추격자,기존 단계·점프·랭킹 회귀를 후속 계획의 구체적인 명령으로 검증한다.
- **Rationale**: 숫자만 바꾸면 경로 삭제와 거리 검사가 새 추격 위치를 처리하지 못한다. 모델·시간·경로·표시를 함께 맞춘다.
