# Decisions: Pixel Stair Game Redesign

- Date: 2026-10-22
- Status: Confirmed
- Workflow: grill-me interview; implementation and planning have not started.

## D01. 추격자가 따라오는 경로
- **Chosen (user)**: 추격자는 플레이어가 오른 것과 같은 계단 경로를 뒤에서 따라온다. 계단의 앞면이 추격자 몸의 일부를 가려 깊이감을 표현한다.
- **Rationale**: 바닥에서 별도로 접근하는 현재 모습 대신, 두 인물이 같은 계단을 오르는 장면으로 보이게 한다.

## D02. 정답과 실수 때의 이동
- **Chosen (user)**: 플레이어가 올바르게 한 칸 오르면 추격자도 경로를 따라 한 칸 이동하여 현재 간격을 유지한다. 실수하면 플레이어는 제자리에 있고 추격자가 한 칸 가까워진다.
- **Existing rule retained**: 시작 간격은 4칸이다. 실수로 줄어든 간격은 정답 입력 때도 그대로 유지한다. 추격자는 자신이 해당 모퉁이에 도착했을 때 방향을 바꿔야 하며, 플레이어가 방향을 바꾸었다는 이유로 즉시 다른 경로로 옮겨가지 않는다.
- **Rationale**: 실제 계단을 따라오는 움직임과 기존 추격 거리 규칙을 일치시킨다.

## D03. 화면 구도
- **Chosen (user)**: 플레이어를 장면 중앙에 두고, 아래에는 지나온 4칸, 위에는 앞으로 갈 5~6칸을 표시한다. 캐릭터와 계단의 크기는 유지한다.
- **Derived constraint**: 게임 시작부터 4칸 뒤의 추격자가 보이도록 시작 발판 아래에도 연결된 계단을 확보한다. 진행 시 중앙의 플레이어를 기준으로 경로가 이동하며, 좁은 화면에서도 앞뒤 경로를 식별할 수 있어야 한다.
- **Rationale**: 장면을 축소하지 않고도 플레이어와 추격자를 함께 볼 수 있다.

## D04. 계단에 가려지는 정도
- **Chosen (user)**: 추격자의 몸 아래쪽만 계단 앞면에 가리고 얼굴과 몸 대부분은 보이게 한다.
- **Rationale**: 계단 뒤에서 따라오는 깊이감과 추격자 위치를 읽기 쉬운 모습을 함께 확보한다.

## D05. 랜덤 계단 구간
- **Chosen (user, revised)**: 한 방향으로 이어지는 계단 구간의 실제 길이를 4~6칸 범위에서 랜덤으로 정한다. 코너를 돌아 새 구간에 들어갈 때는 직전 구간과 다른 길이를 선택한다. 화면에 표시된 경로와 실제 D/J 입력 판정 경로는 일치해야 한다.
- **Selection rule**: 첫 구간은 4·5·6 중 하나다. 이후 직전이 4칸이면 5·6 중, 5칸이면 4·6 중, 6칸이면 4·5 중 하나를 고른다. 한 구간 이상 떨어진 길이의 재등장은 허용한다. 예: 4→6→4는 가능하고 4→4는 불가하다.
- **Derived constraint**: 화면의 5~6칸 미리보기와 구간 전체 길이는 별개다. 긴 구간을 미리보기 끝에서 임의로 꺾지 않는다. J 입력은 방향 전환과 동시에 한 칸 오르므로 구간 길이에 해당 칸을 중복 계산하지 않는다.
- **Rationale**: 짧고 읽기 쉬운 길이 범위 안에서 코너마다 길이가 달라지도록 하여 반복적인 계단 모양을 개선한다.

## D06. 전체 픽셀아트 디자인
- **Chosen (user)**: 게임의 전체적인 디자인을 픽셀아트로 통일한다. 캐릭터, 추격자, 계단, 배경, HUD, 조작 버튼, 설정창을 포함한다.
- **Derived consistency**: 같은 게임 화면에 나타나는 결과 패널, 랭킹, 오디오 설정도 같은 시각 언어를 사용한다. 모바일 조작 버튼, 우측 상단 설정 진입, 게임 안의 HUD 배치는 기존 확정된 흐름에 맞춘다.
- **Rationale**: 장면과 주변 UI가 하나의 게임처럼 보이게 한다.

## D07. 배경 분위기
- **Chosen (user)**: 배경은 회사 건물 내부이며, 창문에 네온 도시 야경이 비친다. 큰 창문이 있는 회사 계단실, 사무실 소품이 보이는 공간, 넓은 유리창과 높은 천장이 있는 회사 로비의 요소를 적절하게 섞는다.
- **Design interpretation**: 계단실을 중심 공간으로 삼고 난간과 층수 표시로 건물 내부임을 드러낸다. 주변에는 책상, 모니터, 복사기 같은 사무실 소품을 배치하며, 로비의 넓은 유리창과 탁 트인 느낌을 더한다. 네온 도시 야경은 창문 너머의 외부 풍경으로 표현한다.
- **Readability constraint**: 소품과 창밖 조명은 배경에 배치하여 실제 계단 경로, 모퉁이, 두 회사원의 움직임과 HUD를 가리지 않게 한다. 이 배치는 사용자의 혼합 선택을 게임 화면에 적용하기 위한 설계 해석이다.
- **Rationale**: 회사 건물 속이라는 장소감, 계단을 오르는 행동, 네온 야경의 분위기를 한 장면에 연결한다.

## D08. 플레이어와 추격자
- **Chosen (user)**: 플레이어는 젊은 회사원, 추격자는 조금 나이 든 회사원으로 표현한다. 두 캐릭터 모두 픽셀아트로 제작한다.
- **Scope clarification**: 추격자를 로봇이나 몬스터로 표현하지 않는다. 두 회사원의 직급이나 상하관계는 별도로 확정하지 않았다.
- **Rationale**: 사용자가 지정한 두 회사원의 추격 구도를 화면에 반영한다.

## D09. 캐릭터 표현과 분위기
- **Chosen (user)**: 코믹하고 귀여운 느낌으로, 표정과 달리기 동작을 과장한 픽셀 캐릭터를 사용한다.
- **Rationale**: 회사원 두 명이 쫓고 쫓기는 모습을 가볍고 알아보기 쉽게 표현한다.

## D10. 기존 잡힘 연출과 게임 동작의 연결
- **Derived from prior confirmed decisions**: 잡혔을 때 접촉 후 시작 간격인 4칸 뒤로 돌아가는 연출을 기존 500ms 회복 안에 끝낸다. 새 경로에서 접촉 위치와 복귀 위치를 계산해야 한다.
- **Existing behavior**: 잡히면 기회가 하나 줄고 거리가 4칸으로 돌아간다. 마지막 잡힘에서도 게임 오버와 점수 저장은 즉시 처리하며, 일반 동작 설정에서는 추격 연출이 끝난 뒤 결과 패널을 표시한다. 동작 줄이기 설정에서는 이동 애니메이션을 끄고 결과를 즉시 표시한다.
- **Scope boundary**: 이 인터뷰는 음악, 효과음, Entra 로그인, 기록 저장 방식의 변경을 요청하지 않았다.
- **Rationale**: 확정된 게임 규칙과 새 장면의 경로 및 디자인을 연결한다.

## Codebase Findings and Planning Constraints
- `src/game/gameEngine.ts`는 현재 `MIN_STRAIGHT_STEPS = 4`, `STRAIGHT_STEP_VARIANTS = 3`으로 직진 입력 횟수를 4~6 범위에서 정한다. 전환 J도 한 칸을 오르므로 새 구간의 실제 길이와 입력 횟수의 관계를 명확히 해야 한다.
- `src/game/StairScene.tsx`의 `getVisibleSteps`는 현재 구간 이후를 항상 5칸씩으로 예측한다. 화면 예측과 실제 무작위 입력 판정이 다른 경로를 사용하고 있다.
- `GameState`에는 현재 방향과 남은 직진 횟수만 있고 지나온 경로나 다음 구간 목록은 없다. 정확한 추격 경로와 미리보기를 위해 경로를 한 곳에서 생성하고 입력 판정과 장면이 공유하도록 계획해야 한다. 이미 지나온 최소 4칸의 경로와 모퉁이를 보존해야 한다.
- `getPursuerTransform`과 `pursuer-caught`는 현재 고정 위치 및 고정 이동 방향을 사용한다. 새 경로의 모퉁이와 계단 앞뒤 관계를 반영하려면 경로 기반 위치 계산과 그리기 순서가 필요하다.
- 기존 애니메이션에서 사용한 UI 전용 임시 상태와 게임 경로 데이터의 역할을 구분한다. 새 경로 모델의 정확한 필드와 타입은 memory-plan 작업 청사진에서 정한다.
- 픽셀아트 확대 시 선명한 모서리를 유지하고 HUD와 설정창의 한글은 읽기 쉬워야 한다.

## Adjacent Finding — Not Added to Confirmed Scope
- `src/game/GameScreen.tsx`의 설정 도움말은 "세 번 실수하면 게임이 끝납니다"라고 안내한다. 실제 엔진은 실수로 거리가 4칸에서 0까지 줄었을 때 기회를 하나 차감한다. 이 도움말과 실제 규칙의 불일치는 별도 수정 검토 항목이며, 이번 인터뷰에서 수정 여부를 확정하지 않았다.
