# Decisions: Character Customization

- Date: 2026-11-03
- Status: Confirmed
- Feature: character-customization
- Source: 사용자와의 캐릭터 꾸미기 인터뷰. 준비된 픽셀 옵션과 색상 선택 방식으로 먼저 테스트하고 이후 조정한다.

## D01. 꾸미는 대상
- **Chosen**: 사용자가 자신의 게임에 표시되는 도망자와 추격자의 외형을 각각 따로 꾸민다.
- **Rationale**: 사용자가 두 캐릭터 모두 선택하고 커스텀하기를 요청했다. 한 캐릭터의 선택이 다른 캐릭터에 자동 복사되지 않도록 한다.

## D02. 선택 항목과 첫 버전의 방식
- **Chosen**: 남녀 캐릭터 표현, 옷, 모자, 안경, 신발, 머리스타일, 피부색을 제공한다. 준비된 픽셀 옵션을 조합하고 제공된 색상을 선택한다.
- **Rationale**: 사용자가 항목을 지정했고, 꾸미기 방식 중 1번인 준비된 픽셀 옵션 조합 및 색상 선택을 확정했다. 첫 버전을 테스트한 뒤 옵션과 표현을 조정한다.
- **Implementation defaults**: 모자와 안경에는 착용하지 않는 선택을 제공한다. 구체적인 옵션 수와 색상 목록은 계획에서 첫 버전에 적합한 작은 카탈로그로 정의한다. 성별 선택과 옷·머리·소품 선택을 독립적으로 조합할 수 있게 한다.

## D03. 화면 진입과 미리보기
- **Chosen**: 타이틀 화면에 `캐릭터 꾸미기` 버튼을 추가한다.
- **Rationale**: 사용자가 타이틀 화면의 별도 버튼을 선택했다.
- **Implementation defaults**: 꾸미기 화면에서 도망자/추격자를 전환하고, 부위 또는 색상을 고르면 해당 캐릭터의 미리보기에 즉시 반영한다. 타이틀 화면으로 돌아갈 수 있게 한다. 모바일에서도 선택 항목과 미리보기를 사용할 수 있게 한다.

## D04. 계정별 자동 저장
- **Chosen**: 로그인 계정에 외형을 자동 저장하고 다른 기기에서 로그인해도 같은 외형을 복원한다.
- **Rationale**: 사용자가 현재 기기에만 저장하는 방식 대신 계정에 자동 저장하는 방식을 선택했다.
- **Code-derived design**: 기존 회사 계정 인증과 Cosmos DB `stair-climb/players`의 계정별 문서를 활용한다. 서버가 인증된 계정의 외형만 읽고 수정한다. 외형 변경은 단계 해금, 단계 최고 기록, 무한 최고 기록과 함께 보존한다.
- **Implementation defaults**: 선택 변경을 잠시 모아서 자동 저장하고 저장 중·저장 실패 상태를 표시한다. 실패한 변경은 화면에 유지하고 재시도할 수 있게 한다. 서버가 저장을 확인하기 전에 저장 완료로 표시하지 않는다. 로그인 계정 변경 시 다른 계정의 외형이나 저장 대기를 적용하지 않는다.

## D05. 외형을 적용하는 장면
- **Chosen**: 단계 모드, 무한 모드, 타이틀의 정지 장면, 퇴근 및 야근 엔딩에 선택한 외형을 일관되게 반영한다.
- **Rationale**: 게임과 엔딩 모두에 꾸민 모습을 반영한다는 인터뷰 내용을 따른다.
- **Code-derived design**: 일반 이동은 `src/game/pixel/PixelOfficer.tsx`, 야근 엔딩은 `src/game/pixel/OvertimeOfficer.tsx`가 별도로 그린다. 두 구현이 같은 외형 설정과 공통 부위 표현을 사용하도록 계획해야 한다.
- **Implementation defaults**: 현재의 캐릭터 역할과 움직임, 발 위치 기준을 유지한다. 새 소품이나 머리 모양이 계단 착지 위치와 추격 판정에 영향을 주지 않게 한다.

## D06. 기존 계정과 기록 호환
- **Chosen**: 외형 저장 이력이 없는 계정도 현재 게임을 이용할 수 있고 기존 기록을 유지한다.
- **Rationale**: 기존 계정 문서에는 외형 데이터가 없다. `SharedProfile`, API 문서 변환, 점수 저장 시 문서를 다시 만드는 경로까지 함께 반영해야 계정 외형과 기록을 모두 보존할 수 있다.
- **Code-derived design**: 외형 값이 없으면 현재 기본 캐릭터를 표시한다. 도망자는 기존 젊은 회사원, 추격자는 기존 나이 든 날씬한 밀짚모자 회사원 외형을 기본으로 한다. 서버는 카탈로그에 있는 옵션과 색상만 허용한다.

## D07. 다음 작업 경계
- **Chosen**: 이번 인터뷰 결과를 바탕으로 `character-customization` 계획을 작성한 뒤 첫 버전을 순차 구현한다.
- **Rationale**: 프로젝트 `AGENTS.md`는 인터뷰 결정문 저장, 계획 파일 작성, Active Task 실행 순서를 지정한다.
- **Existing pending work**: 앞서 요청한 모바일 무한 모드의 좌우 조작 버튼 간격 수정은 `src/game/pixel-theme.css`에 별도 변경으로 남아 있다. 캐릭터 꾸미기 구현 및 배포 시 해당 변경을 보존한다.

## Codebase Notes
- `src/game/pixel/PixelOfficer.tsx`: 현재 `variant`, `direction`, `pose`로 두 캐릭터와 움직임을 그린다. 외형을 파라미터로 전달하도록 확장할 수 있다.
- `src/game/pixel/OvertimeOfficer.tsx`: 야근 장면용 캐릭터를 별도로 그리므로 동일한 옵션을 이곳에도 연결해야 한다.
- `shared/companyRecords.ts`: `SharedProfile`에 아직 외형 필드가 없다.
- `api/src/playerRepository.ts`: 저장 문서를 다시 구성하는 과정에서 알려진 필드만 기록한다. 외형 필드를 점수 저장과 함께 보존하도록 확장해야 한다.
- `src/company/CompanyRecordStore.ts`: 계정별 기록 로딩과 저장 상태를 관리한다. 외형 자동 저장도 계정 전환과 동시 기록 저장을 고려해야 한다.

## 요청 밖의 발견 사항
- 현재 인터뷰에서 별도로 범위를 확장해야 할 추가 결함은 확인하지 않았다.
