# Decisions: Stair Descent Local Test

- Date: 2026-10-28
- Status: Confirmed
- Feature: `stair-descent-local-test`
- Source: 내려오기 로컬 테스트에 대한 grill-me 인터뷰. 기존 게임 유지, 수동 내려오기, 위쪽 추격자, 1단계만, 기존 장애물 유지, 기록 미저장을 사용자가 선택했다.

## D01. 기존 게임 유지와 독립 로컬 진입점

- **Chosen (사용자)**: 기존 계단 오르기 게임은 그대로 두고, 내려오기 게임을 별도 로컬 테스트 버전으로 만든다.
- **Implementation direction (코드 확인으로 정리)**: 로컬 개발 서버의 별도 진입점(예: `/descent-test.html`)과 전용 화면/스타일/표시 모델을 추가한다. 기존 `/`의 `index.html`, `src/main.tsx`, `App.tsx`, 오르기 화면과 게임 규칙 구현은 변경하지 않는다. 기존 순수 엔진/생성기/픽셀 자산은 읽기 전용으로 재사용할 수 있다. 기존 화면에 모드 선택이나 테스트 버튼을 추가할 필요는 없다.
- **Rationale**: 기존 플레이·기록·인증에 영향을 주지 않고 주소를 구분해 로컬에서 조작감을 비교한다. 별도 저장소 복제나 새 게임 엔진/라우터 의존성은 필요하지 않다.

## D02. 수동 내려오기 조작

- **Chosen (사용자)**: D로 현재 방향의 계단 한 칸을 내려간다. J로 좌우 방향을 바꾸며 한 칸 내려간다. Space로 장애물을 넘어 장애물 다음 계단에 착지한다(두 칸 이동).
- **Rationale**: 기존 손 조작을 유지하고 진행 방향의 차이를 테스트한다. 자동 하강이나 자유 낙하는 아니다.
- 모바일도 기존처럼 내려가기/방향 전환/점프 세 버튼을 사용한다. 방향 전환과 점프 버튼은 가까이 배치한다. 같은 입력 한 번이 중복 처리되지 않아야 한다.

## D03. 1단계만 테스트

- **Chosen (사용자)**: 1단계만 제공하며 목표150점, 제한시간90초로 한다. 기존5단계 전체 진행은 이번 실험에 포함하지 않는다.
- **Derived behavior**: 점수0에서 시작하고150점 이상 도달하면 이 테스트의 최종 클리어 결과를 보여준다. 정상 점프/보너스에 의한 목표 초과 점수는 유지한다. 2단계 해금·다음 단계 진행·단계 선택은 제공하지 않는다. 제한시간 만료 또는 추격자에게 잡히면 실패 결과를 보여준다.
- **Rationale**: 1단계의 조작감과 내려오기 연출을 먼저 확인하는 범위다. 재사용 엔진의1단계 체크포인트를 테스트 화면의 최종 클리어로 처리하는 연결이 필요하며, 원래 엔진의 체크포인트 규칙은 바꾸지 않는다.

## D04. 위에서 내려오는 추격자

- **Chosen (사용자)**: 추격자는 플레이어 위쪽, 이미 지나온 계단에서 같은 경로를 따라 내려온다. 기존 추격 방식과 넘어짐 가속을 유지한다.
- **Existing stage-one rules (코드 확인)**: 시작 간격4칸, 평상시800ms마다 한 칸, 잘못 입력하면500ms 동안 플레이어가 넘어지고 그 동안 추격자는250ms마다 이동한다. 먼저 예정된 이동·회복 끝 경계·같은 시각 만료 우선 등 기존 엔진의 시간 판정은 재사용한다. 반복 입력으로 넘어짐을 연장하지 않는다.
- 생명은 없으며 한 번 잡히면 종료한다. 잡힘 연출과 결과 접근, 모션 감소 설정은 기존 동작에 맞춘다.
- **Rationale**: 난이도를 새로 조정하지 않고 하강 방향의 차이를 비교한다. 이번 버전은1단계만이므로 다른 단계의 추격 속도는 사용하지 않는다.

## D05. 계단 경로 유지

- **Chosen (기존 유지 원칙 및 코드 확인)**: 긴 구간5~9칸, 짧은 구간1~3칸과 긴짧긴/긴짧짧긴 혼합, 좌우 전환, 연속 구간 길이 중복 제한을 기존 생성기 그대로 사용한다.
- **Rationale**: 테스트하려는 차이는 오르기에서 내려오기로의 전환이다. 경로 생성과 난수 결정을 함께 바꾸지 않는다.

## D06. 장애물 규칙 그대로 유지

- **Chosen (사용자 명시)**: 기존 장애물 배치·회피·실패 규칙을 유지한다.
- **Existing stage-one rules (코드 확인)**:
  - 긴 구간마다10% 확률로 최대 상자1개를 배치한다. 계단 한 칸마다10%라는 뜻이 아니다.
  - 긴 구간의 시작/끝을 피한 안전한 내부에만 배치하고 짧은 구간에는 배치하지 않는다.
  - 다음 계단이 상자이고 같은 방향으로 안전하게 착지할 수 있을 때 Space로 두 칸 이동한다. 코너를 가로질러 점프하지 않는다.
  - 상자에 일반 이동으로 부딪히거나 상자가 없는데 점프하는 등 잘못된 입력은500ms 넘어짐과250ms 추격 가속으로 처리한다.
  - 이미 생성한 장애물은 resize/설정 열기/재렌더로 다시 추첨하지 않는다.
- **Rationale**: 사용자가 별도로 기존 규칙 유지를 요청했다. 내려오는 화면에서도 다음 상자와 착지 계단을 알아볼 수 있어야 한다.

## D07. 기존 점수·이벤트·일시정지 유지

- **Chosen (기존 유지 원칙 및 코드 확인)**: 정상 이동 한 칸1점, 점프 두 칸2점. 실제 이동한 계단30칸으로30초 보너스를 발동하고 그 동안 한 칸2점/점프4점으로 한다. 게이지와 남은 보너스 시간을 게임 안에 표시한다.
- 설정을 연 동안 제한시간·보너스·추격 시계를 기존 일시정지 규칙에 맞춰 멈춘다. 오디오와 발소리/넘어짐 소리는 기존 컨트롤러를 읽기 전용으로 재사용하며 테스트 화면 생애 종료 시 정리한다. 테스트 내 설정 조정은 메모리에서만 적용한다.
- **Rationale**: 입력·연출 비교에 필요한 기존 피드백을 유지한다. 기존 게임의 오디오 설정 저장값을 테스트에서 덮어쓰지 않는다.

## D08. 테스트 기록 미저장

- **Chosen (사용자)**: 테스트 결과만 보여주고 기록은 저장하지 않는다. 다시 시작하면0점/90초/새 경로/새 이벤트 상태로 시작한다.
- 랭킹/진행도 읽기·쓰기·이관·초기화를 수행하지 않는다. 기존 `stair-climb:leaderboard:v5`, 구랭킹, `stair-climb:stage-progress:v1`, 오디오·인증 저장값을 건드리지 않는다. 테스트 랭킹 화면이나 별도 최고 기록 키도 만들지 않는다.
- **Rationale**: 내려오기 테스트가 기존 기록과 해금에 영향을 주지 않도록 한다. 기존 `GameScreen`을 그대로 장착하면 초기화 시 랭킹 이관과 진행도 저장 효과가 실행되므로 전용 화면이 필요하다.

## D09. 내려오는 화면과 모션

- **Chosen (기존 디자인 유지 및 코드 확인으로 정리)**: 기존 픽셀 회사 건물/네온 야경/젊은 회사원 플레이어/나이 든 회사원 추격자 자산을 유지한다. 다음 계단은 플레이어 아래쪽, 지난 계단과 추격자는 위쪽에 보이게 한다. 카메라는 플레이어를 따라가며 연속해서 내려오는 느낌을 준다.
- 캐릭터/배경/글자 전체를 뒤집지 않는다. 계단 좌표와 이동·점프·추격·잡힘 경로를 내려오는 방향에 맞춘다. 계단 표면/앞면, 상자/캐릭터의 겹침 순서와 점프 중 가림을 확인한다. UI 안내는 '내려가기/내려온 계단'으로 표시한다.
- **Rationale**: 기존 `projectRouteStep`은 index가 증가할수록 화면y가 감소하는 오르기 투영이다. 내려오기 표시 모델에서 세로 투영을 바꾸되 논리 경로 index는 계속 증가시켜 기존 경로·장애물·추격 검증을 유지한다. `stepsClimbed` 등 재사용 엔진 필드는 내부 이동량으로 해석하고 기존 모델 이름을 일괄 변경하지 않는다.

## D10. 로컬 범위와 확인 기준

- **Chosen (사용자 로컬 요청 및 기존 인증 구조 확인)**: 개발용 로컬 데모에서만 테스트 진입을 허용한다. 기존의 `DEV && VITE_LOCAL_DEMO_MODE === 'true'` 조건을 활용하며 실제 Entra 로그인 설정이나 배포 인증을 변경하지 않는다. 테스트 진입점을 기본 배포 게임에 포함시키지 않는다.
- **후속 실행에서 확인할 항목**:
  - 기본 `/`의 기존 게임·스타일·저장 동작이 유지됨.
  - 전용 주소의 D/J/Space·모바일 입력, 내려오는 계단/위에서 따라오는 추격자, 정상/감소 모션의 점프·가림·잡힘 경로.
  - 기존 생성기의 실제 장애물 배치와 두 칸 점프,150점 클리어/90초 실패/단일 잡힘/재시작. 2단계나 다음 체크포인트로 진행하지 않음.
  - 랭킹·진행도·오디오·인증 저장값을 읽고 쓰거나 이관/삭제하지 않음. 테스트 시작/종료/재시작에도 동일함.
  - 좁은 모바일/데스크톱에서 HUD·장애물 안내·세 버튼·설정·결과 접근 가능.
  - 기존 관련 회귀와 새 테스트, lint/build. 실제 브라우저에서 테스트 링크를 열어 확인하되 이 인터뷰 단계에서는 실행하지 않음.
- **Rationale**: 기존 제품을 보존하는 로컬 실험으로 한정하고, 구현 단계에서 비교 가능한 결과를 남긴다.

## 요청 밖 발견 및 제외 범위

- 기존 `GameScreen`은 랭킹 이관과 진행도 저장을 실행한다. 전용 화면 대신 그대로 재사용하면 '기록 미저장' 요구를 어길 수 있으므로 재사용 경계를 계획에서 명시해야 한다.
- 기존 scene/motion에는 오르기 방향 좌표와 앞면 가림 순서가 들어 있다. 화면 전체 반전만으로 내려오기를 구현하면 캐릭터/글자/점프가 잘못 보일 수 있다.
- 새로 발견한 범위 밖 제품 결함은 없다. 기존 번들 크기 개선, 공용 서버 랭킹, Entra 설정/배포, 원본 게임의 단계·난이도 변경, 내려오기5단계 확장은 이번 결정에 추가하지 않는다.
