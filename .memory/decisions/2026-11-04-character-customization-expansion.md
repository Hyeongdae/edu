# Decisions: Character Customization Expansion

- Date: 2026-11-04
- Status: Confirmed
- Feature: character-customization-expansion
- Previous decision: [Character Customization](./2026-11-03-character-customization.md)
- Source: 꾸미기 전체 항목 확장 선택, 가방 종류와 색상 추가, 눈 모양 선택 및 상황별 표정에 대한 사용자 답변.

## D01. 기존 선택지 확장
- **Chosen by user**: 기존 항목을 골고루 늘린다. 장발·곱슬머리, 후드티·조끼, 비니·베레모, 선글라스, 부츠와 추가 색상을 제공한다.
- **Rationale**: 사용자가 전체 항목 확장인 1번을 선택했고 백팩·노트북 가방과 눈 선택도 함께 요청했다.
- **Implementation defaults**: 기존 선택지를 모두 유지한다. 첫 확장의 구체적인 추가 색상은 머리 파랑·분홍, 옷 검정·하늘색·주황·베이지, 신발 남색·빨강·베이지로 잡는다. 기존 피부색 4종과 남녀 표현은 유지한다. 이 색상 목록은 사용자가 개별 지정한 내용이 아닌 첫 버전의 구현 기본안이다.

## D02. 가방 종류와 별도 색상
- **Chosen by user**: 가방은 `없음`, `백팩`, `노트북 가방`, `크로스백`, `서류가방` 중 하나를 고른다. 색상은 `검정`, `갈색`, `남색`, `베이지`를 종류와 독립적으로 고른다.
- **Rationale**: 사용자가 가방 종류와 색상을 따로 고르는 추천안을 선택했다.
- **Implementation defaults**: 두 역할 모두 같은 가방 카탈로그를 사용한다. 백팩은 등에, 노트북 가방·크로스백은 어깨끈과 몸 옆의 가방으로, 서류가방은 손 옆에 표시해 종류를 구분한다. 한 번에 하나만 착용하며 기본값은 가방 없음·검정이다. 가방을 없음으로 바꾸어도 고른 색상은 유지한다.
- **Visual constraints**: 가방이 팔·다리·얼굴을 덮지 않도록 앞뒤 그리기 순서를 나눈다. 이동·방향 전환·넘어짐·앉기·끌려가기에서도 같은 가방을 표시하고 발 위치와 게임 판정을 바꾸지 않는다.

## D03. 눈 모양 5종
- **Chosen by user**: `기본`, `동그란 눈`, `웃는 눈`, `졸린 눈`, `날카로운 눈`을 고른다. 눈동자 색상은 별도로 추가하지 않는다.
- **Rationale**: 사용자가 눈 모양만 선택하는 1번을 선택했다.
- **Implementation defaults**: 기본값은 기존 눈이다. 남녀 표현·머리·안경과 독립적으로 선택한다. 평소 미리보기와 이동 장면에서는 선택한 모양을 구분할 수 있게 그린다. 일반 안경으로 선택한 눈이 일괄 대체되지 않도록 하고 선글라스는 착용 시 눈을 가리는 표현을 허용한다.

## D04. 눈 선택과 상황별 표정
- **Chosen by user**: 평소에는 선택한 눈을 표시하고, 넘어짐·야근 장면에서는 상황에 맞는 표정을 적용한다.
- **Rationale**: 사용자가 기존 상황별 표정을 유지하는 추천안을 선택했다.
- **Code-derived design**: 현재 공통 머리 렌더러는 normal/stumble/weary 표정을 받는다. normal에서 선택한 눈을 쓰고 stumble/weary에서는 기존처럼 놀라거나 지친 눈으로 바꾼다. 상황별 변화는 저장된 눈 선택을 변경하지 않으며 정상 상태로 돌아오면 고른 눈으로 복원한다.

## D05. 두 역할과 모든 장면의 일관성
- **Inherited / code-derived**: 기존 꾸미기와 동일하게 도망자·추격자를 따로 편집한다. 새 선택지는 모두 즉시 사용 가능하며, 타이틀 배경·단계 모드·무한 모드·퇴근 및 야근 엔딩·미리보기에 함께 반영한다.
- **Rationale**: 이미 두 역할의 외형을 공통으로 전달하는 구조가 구현되어 있다. 새 항목만 특정 모드나 엔딩에서 빠지지 않도록 같은 부위 렌더링을 활용한다.
- **Implementation defaults**: 현재 타이틀의 꾸미기 창을 확장한다. 가방/가방 색상/눈 모양을 접근 가능한 선택 그룹으로 제공하고 늘어난 옵션을 모바일에서도 스크롤하여 고를 수 있게 한다. 미리보기의 가방·장발·부츠가 잘리지 않도록 확인하되 실제 게임의 착지 기준과 계단 좌표는 유지한다.

## D06. 기존 외형과 계정 기록 보존
- **Code-derived design**: 새 외형은 눈 모양·가방·가방 색상 필드를 포함하는 version 2로 명시한다. 기존 version 1 문서는 기존의 모든 선택을 보존하고 새 필드만 기본 눈·가방 없음·검정으로 보완하여 읽는다. 새 저장은 version 2를 사용한다.
- **Rationale**: 현재 shared/characterAppearance.ts는 version 1과 정확한 필드 집합을 검사한다. 새 필드만 일괄 필수로 추가하면 기존 외형을 잘못된 데이터로 판정하여 기본 캐릭터로 되돌릴 수 있다.
- **Implementation constraints**: 저장소 디코딩, 클라이언트 응답 해석, 초깃값 정규화, 외형 비교·복사, 단계/무한 점수 저장의 외형 보존을 함께 검증한다. 읽기만으로 Cosmos 문서를 대량 갱신하지 않는다. 기존 점수·해금 단계·랭킹은 그대로 보존한다.
- **Release boundary**: 클라이언트와 API는 같은 확장 계약으로 함께 반영한다. 구버전 UI를 계속 실행하는 탭에 새 선택지를 제공하는 것은 보장하지 않으며 배포 후에는 새로고침하여 최신 화면을 사용한다. version 1 데이터의 보존과 구버전 실행 코드의 지원은 구분한다.

## D07. 저장과 오류 처리
- **Inherited / code-derived**: 기존 Cosmos DB stair-climb/players의 로그인 계정별 문서에 저장한다. 새 컨테이너·DB·인덱스는 만들지 않는다.
- **Rationale**: 외형 저장, 400ms 자동 저장, 저장 상태·실패 재시도와 계정 분리가 이미 구현되어 있다.
- **Implementation defaults**: 선택한 외형은 즉시 표시하고 기존 자동 저장을 사용한다. 로컬 데모는 메모리에서만 유지한다. 기존 ETag 조건부 쓰기와 점수 저장 직렬 처리, 늦은 저장 응답으로 새 선택을 되돌리지 않는 처리를 유지한다.

## D08. 다음 작업 경계
- **Workflow**: 이 인터뷰는 결정문 저장으로 종료한다. 다음 명령은 `/memory-plan character-customization-expansion`이며, 계획을 작성한 뒤 Active Task를 순서대로 실행한다.
- **Scope**: 이번 단계는 구현·테스트 실행·커밋·푸시·배포를 포함하지 않는다. 기존 완료 계획과 current.md 포인터를 새 계획 작성 전에 바꾸지 않는다.
- **Existing pending change**: src/game/pixel-theme.css의 기존 미커밋 모바일 무한 모드 조작 버튼 간격 변경을 보존한다.

## 요청 밖의 발견 사항
- 추가 범위를 정해야 하는 별도 결함은 발견하지 않았다. 눈/안경 중복 그리기와 version 1 호환은 새 선택지 구현에 직접 필요한 연결 작업이다.
- 이전 계획의 실제 Cosmos emulator 통합 검증과 운영 계정 저장 확인은 여전히 배포 전후 확인 대상으로 남아 있다. 이번 인터뷰에서 배포 범위로 추가하지 않는다.
