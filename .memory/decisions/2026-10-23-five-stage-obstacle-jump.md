# Decisions: Five Stage Obstacle Jump

- Date: 2026-10-23
- Status: Confirmed
- Revision: 계단 길이·패턴, 장애물 확률·배치 구간, 시간 기반 추격과 오입력 벌점은 [2026-10-23 후속 결정](./2026-10-23-five-stage-chase-route-revision.md)이 우선한다. 아래 원 기록은 변경 이력으로 보존한다.
- Workflow: grill-me. 사용자 선택과 기존 코드에서 유지할 규칙을 구분해 기록한다. 구현·계획·테스트·실제 랭킹 삭제는 아직 수행하지 않았다.

## D01. 5단계 제한시간과 목표
- **Chosen (user)**: 총5단계로 구성하고 단계별 제한시간은90/75/65/60/50초로 한다.
- **Chosen (user)**: 각 단계에서300점씩 추가 획득한다. 누적 목표는300/600/900/1200/1500점이다.

| 단계 | 해당 단계 제한시간 | 누적 목표 점수 | 직선 구간당 장애물 등장 확률 |
| :--- | :--- | :--- | :--- |
| 1 | 01:30 (90초) | 300점 | 20% |
| 2 | 01:15 (75초) | 600점 | 35% |
| 3 | 01:05 (65초) | 900점 | 50% |
| 4 | 01:00 (60초) | 1200점 | 65% |
| 5 | 00:50 (50초) | 1500점 | 80% |

- **Scope change**: 기존 '2단계는 무제한 계속 플레이'를 위5단계 규칙으로 대체한다.6단계나 클리어 후 무제한 모드는 추가하지 않는다.
- **Derived scoring contract**: 실제 누적 점수로 판정한다. 일반 오르기/점프/더블 점수 이벤트를 모두 반영하며 목표 이상이면 성공이다. 초과 점수를 자르거나 점수를0으로 되돌리지 않는다. 예:299→301이면2단계, 다음 목표는600점이다.
- **Rationale**: 사용자가 선택한300점 간격과 짧아지는 제한시간, 늘어나는 장애물로 난이도를 올린다.

## D02. 승급 회복과 시간 재시작
- **Chosen (user)**: 1→2,2→3,3→4,4→5 승급 때마다 기회3회·추격자 거리4칸으로 회복한다.
- **Chosen (user)**: 누적 점수와 보너스는 유지하고 새 단계의 제한시간을 시작한다.
- **Existing behavior retained**: 올라온 계단/현재 위치/방향/경로도 유지한다. 남은 이전 단계 시간은 새 시간에 더하지 않는다. 게임 시작/재시작은1단계90초이고 대기 중에는 줄지 않는다.
- **Rationale**: 기존 승급 보상을 모든 새 단계에 동일하게 적용하면서 목표 점수와 경로가 끊기지 않게 한다.

## D03. 제한시간 만료와 최종 클리어
- **Chosen (user)**: 5단계에서 누적1500점 이상이면 최종 클리어로 종료하고 결과/랭킹을 저장한다.
- **Existing boundary retained**: 모든 단계에서 만료 시각을 입력보다 먼저 판정한다. 마감 이상인 입력은 점수를 얻거나 승급/클리어하지 못한다. 제한시간 안에 해당 목표를 채우지 못하면 현재 도달 단계로 종료한다.
- **Existing lifecycle retained**: 무입력/화면 복귀에도 만료를 확인한다. 회복500ms 동안에도 시간이 흐른다. 설정창에서는 단계/보너스 시계를 함께 멈추고 닫을 때 한 번만 보정한다. 일반 숨김 탭의 시간은 계속 센다.
- **Derived result contract**: 최종 클리어/시간 초과/잡힘을 결과에서 구분한다. 클리어와 시간 초과에 잡힘 연출/기회 차감을 만들지 않는다. 기존 마지막 잡힘의500ms 공개와 reduced-motion 동작을 유지한다.
- **Persistence retained**: 게임이 종료될 때만 최종 기록을1회 저장한다. 중간 승급 때마다 새 랭킹을 저장하지 않는다.
- **Rationale**: 이전 시간/입력 경계를5단계 전체로 확장하고 최종 성공을 실패와 구분한다.

## D04. 직선 구간 길이
- **Chosen (user)**: 같은 방향으로 이어지는 계단 구간 길이를4~8칸 랜덤으로 변경한다.
- **Existing generation convention retained**: 직전 구간과 같은 길이는 연달아 선택하지 않는다. 구간이 끝나면 방향을 번갈아 바꾸는 구조, 플레이어/추격자/미리보기가 같은 경로를 사용하는 구조를 유지한다.
- **Rationale**: 장애물을 읽고 점프할 공간을 확보하면서 길이가 반복되어 단조로워지는 것을 줄인다.

## D05. 장애물 위치와 단계별 확률
- **Chosen (user)**: 장애물은 직선 구간에만 배치한다. 모퉁이를 가로지르는 점프나 점프 중 자동 방향 전환은 추가하지 않는다.
- **Chosen (user)**: 표의20/35/50/65/80%는 '직선 구간 하나에 장애물이 등장할 확률'이며 구간당 최대1개다. 계단 한 칸마다 같은 확률로 여러 개를 만드는 뜻이 아니다.
- **Derived placement contract**: 길이L인 구간에서 첫 칸/마지막 칸을 제외한2~L-1번째 칸 중 한 곳을 선택한다. 점프 출발·장애물·착지 계단의 방향이 같아야 하며 착지 칸은 비어 있어야 한다. 장애물은 시작 위치/뒤쪽 이력/착지 칸에 갑자기 새로 생기지 않는다.
- **Code-derived consistency contract**: 이미 확정/표시한 장애물을 렌더링·resize·재입력 때 다시 뽑지 않는다. 승급 직후 눈앞의 장애물을 교체하지 않고 새로 생성/확정할 미래 구간에 새 확률을 적용한다. 플레이어/장면/충돌 판정은 동일한 장애물 데이터를 사용한다.
- **Visual scope**: 기존 회사 내부 픽셀 스타일과 구분되는 고정 장애물 한 종류를 사용한다. 움직이는 장애물/아이템/장애물별 다른 능력/새 배경은 추가하지 않는다. 구체적인 도형·색상은 계획에서 기존 픽셀 컴포넌트에 맞춰 정한다.
- **Rationale**: 짧은4칸 구간도 출발/착지가 가능한 위치에만 배치하고, 화면의 미리보기와 실제 충돌을 일치시킨다.

## D06. 스페이스바 점프
- **Chosen (user)**: 스페이스바로 다음 계단의 장애물을 건너 그다음 계단에 착지한다. 현재n번째에서 n+1에 장애물이 있으면 n+2로 이동하는2칸 점프다.
- **Derived eligibility**: 다음 칸에 장애물이 있고 같은 직선 방향의 비어 있는 착지 칸이 확보되어야 성공한다. 장애물을 밟고 올라간 뒤 점프하는 방식이 아니다. 착지 후 같은 경로와 방향을 이어간다.
- **Chosen (user)**: 다음 칸에 장애물이 없을 때 점프하면 오입력으로 넘어지고 추격자가1칸 가까워진다. 빈 곳에서 자유 점프/입력 무시를 허용하지 않는다.
- **Rationale**: 장애물을 보고 세 번째 조작을 선택하도록 하고 스페이스바로 모든 계단을 빠르게 건너뛰는 방식을 막는다.

## D07. 점프 점수와30계단 이벤트
- **Chosen (user)**: 성공 점프는 실제2칸 이동으로 집계한다. 기본2점, 더블 점수 이벤트 중4점이며 이벤트 충전도2칸으로 센다. 표시용 점수만 올리고 실제 위치를1칸만 이동시키지 않는다.
- **Existing bonus rules retained**:30계단 도달 시30초 더블 점수 이벤트를 사용하고 활성 중에는 다음 이벤트를 중복 충전하지 않는다. 단계 승급 때문에 진행 중 이벤트/게이지/음악 속도를 초기화하지 않는다.
- **Derived atomic-input boundary**: 기존 엔진처럼 한 입력의 시작 시점에 이벤트 만료/활성을 판정한다. 점프 도중 두 번째 칸에만 새 이벤트 배율을 적용하지 않는다. 비활성 게이지28/29에서 점프하면 우선 기본2점을 얻고 이동 완료 후30초 이벤트를 시작해 게이지를0으로 둔다. 초과 충전분을 다음 이벤트로 이월하지 않는다. 이벤트가 이미 활성인 점프는4점이다.
- **Derived simultaneous boundary**: 같은 점프에서 목표 점수와 이벤트 시작이 함께 충족되면 실제 점수/2칸 경로 이동/새 이벤트를 완성한 뒤 한 번만 승급하거나 최종 클리어한다.
- **Rationale**: 사용자가 선택한 거리2칸과 기본2/보너스4점 규칙을 기존 '입력 완료 후 이벤트 발동' 순서에 맞춘다.

## D08. 장애물 충돌과 오입력
- **Chosen (user)**: 장애물을 점프하지 않고 밟으려 하면 기존 오입력과 동일하게 제자리에서500ms 넘어지고 추격자만1칸 가까워진다. 즉시 목숨 차감/즉시 게임 종료를 추가하지 않는다.
- **Existing rules retained**: 추격 거리가0이 되어 잡혔을 때만 기회1회를 잃고 거리는4칸으로 돌아간다. 기회가0이면 종료한다. 실패한 입력은 점수/계단/이벤트 충전을 주지 않는다.
- **Existing input blocking retained**: 회복 중 연속 입력, 대기/종료/설정창에서 차단된 입력은 새 실수로 중복 처리하지 않는다. 잘못 누른 J와 장애물 없는 점프도 같은 실패 처리다.
- **Scope-preserving pursuit contract**: 장애물은 플레이어의 조작 과제다. 장애물 때문에 추격자가 멈추거나 기회를 잃는 새 규칙은 추가하지 않는다. 플레이어가2칸 성공 이동하면 추격자도 기존 경로에서2칸 진행해 논리적 추격 거리를 유지한다. 거리 변화는 기존 오입력/승급 규칙을 따른다.
- **Rationale**: 장애물과 기존 추격/기회 체계를 함께 사용하면서 이중 벌점과 새 추격 난이도 규칙을 만들지 않는다.

## D09. 빠른 반응과 모바일 버튼
- **Chosen (user, revised layout)**: 모바일 버튼은 앞으로 / 방향 바꾸기 / 점프 순서이며 방향 바꾸기와 점프를 가까이 붙여 연속 조작하기 쉽게 한다. 앞서 제안했던 앞으로 / 점프 / 방향 바꾸기 순서는 채택하지 않았다.
- **Derived interaction contract**: 기존 성공 오르기처럼 점프 애니메이션 완료를 기다리는 별도 입력 잠금을 추가하지 않는다. 한 번의 유효한 조작은 한 번만 처리하고 곧바로 다음 조작에 반응한다. 실제 실패 회복500ms/설정 차단은 유지한다.
- **Code-derived browser contract**: 게임 조작 중 스페이스바의 페이지 스크롤을 방지하되 설정/텍스트 입력의 키 처리는 기존처럼 보호한다. 스페이스 길게 누르기의 자동 repeat를 새로운 점프로 중복 처리하지 않는다. 한 모바일 탭에서 pointer/click이 이중 실행되지 않아야 한다.
- **Accessibility retained**: 가까운 배치는 간격 조정으로 구현하고 기존 최소56px 수준의 터치 타깃·명확한 라벨·키보드 접근성·큰 글자/내부 스크롤을 유지한다. 방향 바꾸기와 점프의 터치 영역은 겹치지 않는다.
- **Rationale**: 사용자가 요청한 빠른 전환을 지원하면서 브라우저 스크롤/중복 입력/오터치를 막는다.

## D10. 점프 표시·HUD·효과음
- **Derived presentation**:2칸을 건너뛰는 점프를 일반 한 칸 오르기와 구분되는 공중 이동/착지 모션으로 보여 준다. 장애물은 캐릭터/계단과 시각적으로 구분되며 성공 후 실제 착지 위치와 카메라가 일치해야 한다. reduced-motion에서는 과한 움직임을 줄여도 위치/성공·실패 피드백은 유지한다.
- **HUD continuity**: 현재 단계1~5, 현재 누적 목표, 남은 분:초, 누적 점수, 기회, 기존 이벤트 게이지를 게임 내부에 유지한다. 더 이상2단계를 '제한 없음'으로 표시하지 않는다. 최종 클리어는 결과에서 명확하게 표시한다.
- **Existing audio scope retained**: 현재의 오르기/넘어짐 효과음 연결과 독립 볼륨/음소거를 재사용한다. 성공 점프 한 번의 착지에 성공 효과음을 한 번 호출하고 점수2/4라고 같은 효과음을 중복 호출하지 않는다. 새 점프 음원 도입이나 전체 볼륨 변경은 이번 선택에 포함하지 않았다.
- **Known separate issue**: 사용자가 보고한 '넘어짐 소리만 들리지 않음'은 별도 `2026-10-23-fall-sound-playback-fix.md`에 확정되어 있지만 아직 계획/구현하지 않았다. 이 결정문만으로 해당 문제가 해결되었다고 보고하지 않는다. 코드 경로를 재사용하는 것과 실제 청취 문제 해결을 구분한다.
- **Rationale**: 게임 전체 스타일/기존 오디오를 유지하면서 새로운 점프 조작의 결과를 이해할 수 있게 한다.

## D11. 랭킹 비교와 기존 기록 삭제
- **Chosen (user)**: 도달 단계가 높은 기록을 먼저 표시하고 같은 단계에서는 점수가 높은 기록을 먼저 표시한다.
- **Chosen (user)**: 기존 기록을 삭제하고 새5단계 규칙의 랭킹을 시작한다. 구형 기록 보관/합산은 채택하지 않았다.
- **Existing tie/best rules retained**: 단계/점수가 완전히 같으면 먼저 달성한 기록을 우선하고 개인의 동점 기록은 달성시각을 갱신하지 않는다. 개인 최고는 같은 한 판의 단계/점수 쌍으로 갱신한다. 현재 브라우저 TOP10/현재 사용자 강조를 유지한다.
- **Derived version boundary**: 새 형식은 `stair-climb:leaderboard:v3` JSON 배열을 사용하고 bestStage는1~5를 허용한다. 기존v1/v2 랭킹 키만 정리한다. v2의2단계 무제한 기록을 새 단계/클리어 기록으로 임의 변환하지 않는다.
- **Deletion scope**: 새 기능 적용 후 초기 읽기/저장 경로에서 구형 랭킹을 한 번 정리할 수 있게 한다. 존재 여부를 확인해 반복 실행해도 유효한v3를 삭제하지 않는다. 오디오 설정/인증/다른 키는 보존하며 `localStorage.clear()`를 사용하지 않는다. 인터뷰 단계에서 실제 저장소를 삭제하지 않는다.
- **Failure behavior retained**: 저장소 접근/삭제/저장이 실패해도 게임/결과/재시작을 유지하고 최종 저장 실패를 알린다. 새 서버 공유 랭킹/외부 서비스는 추가하지 않는다.
- **Rationale**: 사용자가 승인한 초기화로 기존 무제한2단계 기록과 다른 규칙의 성적을 섞지 않고, 현재 단계 중심 비교를 유지한다.

## D12. 구현 전 확인한 구조와 후속 검증 범위
- **Code-derived**: 현재 GameStage는1|2, GameInput은forward|turn, StairRunLength는4|5|6이고 장애물 데이터가 없다. 단계/입력/구간 길이/경로·장애물 상태와 랭킹 runtime 검증을 함께 확장해야 한다.

- **Code-derived**: 현재 점수 증가2점을 이벤트 피드백으로 취급하는 부분은 '일반 점프2점/보너스 점프4점'을 구분할 수 있게 검토해야 한다. 단계 목표/Space 안내/모바일3개 버튼과 실제 입력 규칙도 함께 맞춰야 한다.

- **Verification direction**: 점프 성공/실패/회복 경계/코너 제외/안전 착지,4~8칸과 직전 길이 비반복,단계별 확률과 구간당 최대1개,표시와 판정의 일치,마감 우선/점수 초과/이벤트 경계/최종 클리어,승급 회복,랭킹v1/v2만 정리,Space와빠른 터치/큰 글자/정상·reduced-motion을 검증한다. 정확한 파일·심볼·타입·검증 명령은 후속 memory-plan 청사진에서 정한다.
