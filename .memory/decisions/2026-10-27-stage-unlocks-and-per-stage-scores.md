## D01. 클리어하면 다음 단계 해금

- **Chosen — 사용자 선택**: 1단계를 클리어하면 2단계가 열린다. 체크포인트에서 그만둔 후 다시 시도하거나 나중에 접속해도 다음 단계부터 시작할 수 있어야 한다. 기존의 클리어한 단계까지만 선택하는 규칙을 대체한다.
- **Derived — 해금 범위**: 최고 클리어 단계를 H라고 하면 1~min(5,H+1)을 선택할 수 있다. 최초 H=0은 1단계만 가능하고, H=1은 1~2단계, H=4/5는 1~5단계다. 6단계는 만들지 않는다.
- **Derived — 기본 선택**: 사용자가 보고한 재시도 흐름을 위해 가장 높은 해금 단계를 기본 선택한다. 예를 들어 1단계 클리어 후 그만두기→다시 시도는 2단계가 기본 선택된 단계 선택창으로 돌아간다. 시작하기를 눌러야 실제 플레이가 시작되며 낮은 해금 단계를 직접 선택할 수도 있다.
- **Derived — 저장**: 클리어 이력은 계정별 최고값으로 저장하며 실패나 낮은 단계 재도전으로 낮아지지 않는다. 기존 클리어 이력에도 같은 해금 공식을 적용한다. 단순히 도전했다는 사실을 클리어로 저장하지 않는다.
- **Rationale**: 클리어한 다음 도전을 재접속과 재시도에서도 선택할 수 있어야 한다.

## D02. 단계마다 점수 0점으로 시작

- **Chosen — 사용자 선택**: 1단계 목표는150점이고 이후 단계마다50점씩 올린다. 각 단계에서 점수를0점부터 시작한다. 누적400점 목표나 이전 단계 점수 합산 방식을 대체한다.

| 단계 | 시작 점수 | 해당 단계 클리어 목표 | 제한시간(유지) |
| :--- | :--- | :--- | :--- |
| 1 | 0 | 150 | 90초 |
| 2 | 0 | 200 | 75초 |
| 3 | 0 | 250 | 65초 |
| 4 | 0 | 300 | 60초 |
| 5 | 0 | 350 | 50초 |

- **Derived — 판정**: 단계 s의 목표는150+50×(s−1)이다. 그 단계 점수가 목표 이상일 때 클리어한다. HUD와 실제 판정은 같은 단계별 목표를 사용한다.
- **Derived — 점수 초과**: 점프/보너스 득점으로 목표를 초과하면 실제 점수를 클리어 화면과 해당 기록에 사용한다. 예를 들어149점에서 일반 점프 성공 시151점으로 클리어한다. 다음 단계에서는 초과분을 포함해 이전 점수를 넘기지 않고0점으로 시작한다.
- **Derived — 시작 경로**: 단계 선택에서 바로 시작하는 경우도 해당 단계0점/해당 목표/온전한 제한시간이다. 점수 증가 알림 등 이전 단계의 점수 표현이 다음 단계에 남지 않도록 한다.
- **Rationale**: 단계별 목표와 그 단계의 플레이 성과가 분명하게 보여야 한다.

## D03. 체크포인트 계속/그만두기 유지

- **Chosen — 사용자 선택1**: 1~4단계 클리어 시 체크포인트에서 계속하기/그만두기를 묻는다. 자동 전환하지 않는다. 계속하기를 누르면 다음 단계에서0점으로 시작한다.
- **Derived — 종료 기록**: 그만두기는 방금 클리어한 단계와 그 단계의 실제 점수로 종료한다. 아직 시작하지 않은 다음 단계0점으로 기록하지 않는다.
- **Derived — 기존 동결 유지**: 선택 동안 단계 제한시간·추격자·보너스 시간을 멈춘다. 계속하기에서 다음 단계의 온전한 제한시간/일반 추격 간격과 추격자4칸 뒤 간격을 적용한다. 5단계는 최종 클리어 결과로 종료한다.
- **Derived — 점수 외 기존 계약 유지**: 점수 초기화 외의 계속하기 동작은 유지한다. 경로/이미 결정된 장애물/계단 수/이벤트 게이지와 보너스 잔여시간을 이어가고 대기 시간을 한 번만 보정한다. 단계 선택을 통한 새 판은 기존처럼 새 경로·이벤트0부터 시작한다.
- **Rationale**: 사용자가 계속 도전할지 선택하는 기존 흐름과 새 단계별 점수 방식을 함께 적용한다.

## D04. 랭킹은 실제 종료 단계와 그 단계 점수

- **Chosen — 사용자 예시**: `2단계 · 80점`, `3단계 · 150점`처럼 기록한다. 이전 단계에서 획득한 점수를 합산하지 않는다.
- **Derived — 도전 단계 의미**: 2단계에서80점을 얻고 잡히거나 시간이 끝나면2단계80점이다. 그 단계를 아직 클리어하지 못했어도 실제 도전한 단계를 기록한다. 최초1단계 도전 중 종료도1단계/그 단계 점수이며 옛 미클리어0단계 규칙을 대체한다.
- **Derived — 과거 클리어와 분리**: 이전에3단계를 클리어했어도 이번에1단계를 선택해80점으로 종료하면 이번 기록 후보는1단계80점이다. 이전 최고 클리어 값을 이번 랭킹 단계로 물려주지 않는다. 실제 클리어 이력은 해금용으로 별도 유지한다.
- **Derived — 정렬/개인 최고 보존**: 높은 단계 우선, 같은 단계에서는 해당 단계 점수가 높은 기록 우선이다. 계정별 개인 최고 한 건을 유지하고 더 좋은 단계·점수 쌍일 때만 이름/시각을 함께 교체한다. 동일 단계·점수의 기존 달성 시각 보존과 동점 정렬, TOP10/현재 사용자 표시는 유지한다.
- **Derived — 예시**: 3단계10점은2단계200점보다 높다. 2단계120점은2단계80점보다 높다. 1단계151점에서그만두기는1단계151점이며, 이후2단계를시작해80점으로종료하면2단계80점이더높다.
- **Derived — 저장 경계**: 클리어 이력은 실제 클리어 즉시 저장한다. 랭킹 비교/저장은 그만두기·잡힘·시간초과·최종클리어로 종료될 때 한 번만 수행한다. 단계 선택 미리보기나 체크포인트 대기 자체로 새 랭킹을 만들지 않는다.
- **Rationale**: 사용자 예시는 클리어 단계+누적 점수가 아닌 도전한 단계+해당 단계 점수다. 랭킹의 단계와 해금용 클리어 단계를 분리해야 한다.

## D05. 기존 랭킹만 초기화, 진행도 보존

- **Chosen — 사용자 선택1**: 이전 규칙의 랭킹만 초기화한다. 클리어 이력과 그에 따른 단계 해금은 유지한다.
- **Derived — 새 형식**: 새 기록은 별도 버전(`stair-climb:leaderboard:v5`)으로 구분하고 실제 플레이 단계1~5를 검증한다. 이전v4의 클리어 단계/누적 점수를 새 도전 단계/단계별 점수로 변환하거나 혼합하지 않는다. 새 형식 기록은 이후 새로고침에서 다시 초기화하지 않는다.
- **Derived — 진행도 유지**: 계정별 `stair-climb:stage-progress:v1`의 최고 클리어 값을 유지한다. 기존 코드는 v4 최고 기록에서도 클리어 이력을 복구하므로, 구 기록 정리 전에 유효한 v4 클리어 이력을 기존 진행도와 합쳐 보존할 필요가 있다. 저장 실패 시 이 복구 근거를 먼저 지워 진행도를 잃지 않도록 후속 계획에서 처리한다.
- **Derived — 새 랭킹으로 해금 추론 금지**: v5의2단계80점은2단계 클리어를 뜻하지 않는다. 이를 최고 클리어 값으로 가져와3단계를 열면 안 된다. 해금은 실제 클리어 이력을 기준으로 한다.
- **Derived — 초기화 범위**: 진행도·오디오 설정·인증·다른 저장값은 초기화하지 않는다. 이 인터뷰에서는 실제 브라우저 저장소를 지우지 않는다. 후속 구현에서 구 랭킹과 새 랭킹의 버전 경계를 처리한다.
- **Rationale**: 기존 누적 점수와 단계별 점수는 비교할 수 없지만, 사용자가 얻은 진행도는 유지해야 한다.

- 새 규칙에 영향을 받는 안내·선택창·체크포인트·결과/랭킹·저장 마이그레이션 및 관련 엔진/UI/브라우저 검증을 후속 계획에 포함한다. 완료된 기존 계획/Task를 다시 미완료로 돌리지 않는다.
